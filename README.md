# 角色工坊 / Character Forge

Windows 本地角色生成工作台：自备 LLM、生图接口及 Tripo 账号，按「角色设定 → 角色图片 → 部件拆分 → 部件建模」逐步制作角色，再组装到自己的 Blender 骨架。

## 启动

当前环境已安装依赖并构建界面。**双击 `start.cmd` 或 `start-desktop.cmd`** 打开桌面版，自动启动本地服务并显示角色工坊。

普通浏览器版使用 `start-browser.cmd`，地址为 **http://127.0.0.1:8765**。

关闭桌面主窗口会退出应用，并停止本次由桌面版启动的服务；已在外部启动的服务不会被关闭。再次运行会继续使用本地项目和 Tripo 登录状态。若提示旧版服务正在运行，先关闭原来的启动窗口。

在另一台 Windows 电脑首次使用时：安装 Python 3.11+、Node.js 22.12+（建议 24 LTS），运行 `install.cmd`，再运行 `start.cmd`。无须修改 PowerShell 执行策略，也无须管理员权限。

## 配置

点击左下角 **模型与工具设置**。所有路径可随时修改，不写死在工作流程中。

| 配置 | 说明 |
|---|---|
| LLM | OpenAI 兼容 Base URL、模型名、API Key；支持 `/chat/completions` 的 `tools/tool_choice` |
| 生图 | OpenAI 兼容 Base URL、图像模型名、API Key、宽屏尺寸、响应格式 |
| Tripo | 默认网页会员模式，无需 API Key；可显式切换到独立计费的开发者 API 模式 |
| Blender | 指定 `blender.exe`，也接受同目录存在该程序的 `blender-launcher.exe` |
| 模板 | 指定包含人体网格与目标骨架的 `.blend` 文件 |
| 权重源 | 可设置骨架对象、身体网格、头部网格及最大影响数 |
| 输出目录 | 每个项目 / 任务单独保存；不覆盖模板或旧结果 |

预置模板配置：

```text
程序：C:\Program Files\Blender Foundation\Blender 5.2\blender-launcher.exe
模板：D:\独立游戏\Client\Role1\骨骼和身体.blend
骨架：_COM
身体：Mesh_Skin_Body
头部：Mesh_Skin_Head
最大骨骼影响：4
```

密钥使用 **Windows DPAPI** 按当前系统用户加密保存，接口不会将已有密钥返回给浏览器。密码输入框留空表示保留已有密钥。也可通过环境变量提供 `CHARACTER_FORGE_LLM_KEY`、`CHARACTER_FORGE_IMAGE_KEY`、`CHARACTER_FORGE_TRIPO_KEY`。不要把密钥放进提示词、截图、仓库或 README。

### 生图兼容协议

- 无参考图：`POST {base_url}/images/generations`，JSON 包含 `model/prompt/n/size`。
- 有参考图：`POST {base_url}/images/edits`，multipart 包含同名字段及一个或多个 `image[]` PNG 文件。
- 响应：`data[0].b64_json` 或 `data[0].url`。响应格式选“不传 / 自动”可兼容不接受 `response_format` 的模型。
- Base URL 通常以 `/v1` 结尾，不要填完整的 `/images/generations` 路径。
- “OpenAI 兼容”不等于支持参考图。服务必须实际提供上述编辑接口；自定义异步协议、聊天式生图或其他字段目前需要额外适配。
- 参考图最多 8 张，每张最多 25 MB / 3600 万像素。只有开启 LLM 图片理解时，参考图才会额外发给设计助手。

### Tripo 网页会员工作台（默认）

1. 打开桌面版，选择角色，进入 **部件建模** 并选择部件，依次完成独立部件图、部件三视图和裁切确认，再进入 **生成模型**。
2. 点击 **一键生成并预览**。已登录时直接后台执行，不弹出工作台；需要登录时才弹出 Tripo 登录窗口。
3. 在弹窗中完成登录，窗口会自动收起并继续，不需要再次点“继续任务”。登录会话与普通 Chrome 独立，保存在本机；关闭登录弹窗会暂停任务，可以稍后点“继续任务”重新登录。
4. 程序在后台切换 **智能网格 P2.0 / 多视图**，上传到对应视角槽，设置 **三角面、15,000 面、生成 1 个**，再提交网页生成。主界面显示进度。这些默认参数可在工具设置中修改；API 模型参数独立。
5. 程序跟踪本次生成版本，完成后选择 **GLB** 导出，下载、校验并回填原角色。当前角色的页面会自动切到模型预览，然后可以进入骨架适配。切换角色不会改变下载归属。

点击一键生成会按网页登录账号消耗 Studio 额度，实际消耗以网页为准。登录过期时再次弹出登录窗口，成功后自动继续；其他验证、弹窗或网页异常导致操作受阻时会暂停并显示工作台供处理，再点击 **继续任务**。**暂停自动操作** 只暂停本地操作/跟踪，不撤销已经提交的云端生成或已经发起的下载。未提交的暂停任务可以取消，再使用新的图片或参数开始。

自动操作过程中请勿手动更换网页图片、选中其他模型或再次点击网页生成按钮。每次任务固定使用开始时的裁切快照和参数；改过参数后，要先取消未提交任务或完成已有任务，再开始新的任务。

需要查看网页或手动操作时，仍可主动点击 **打开内置 Tripo 工作台**。工具栏提供 **下载文件夹**、**导入已下载 GLB**、**刷新网页**和 **系统浏览器打开**。若登录方式不支持内置浏览器，可在系统浏览器生成并下载，再手动选择 GLB 导入。

若 Windows 使用本机手动代理，首次打开工作台时会分别检查认证、账号资料及会员服务（`auth-cn.tripo3d.com`、`api-cn.tripo3d.com`、`msapi.tripo3d.com`）。只将代理连接失败且直连正常的域名加入绕行列表，其他请求保留原代理及例外规则。检查只发送不含账号的 OPTIONS 请求；不会发送验证码。此调整仅作用于内置工作台会话，代理配置变更后请重启应用。脱敏网络错误记录在 `data/desktop/studio-network.jsonl`，仅含域名、步骤分类、请求方法、状态及网络错误码，不记录手机号、验证码、令牌或请求内容；未登录时出现 session/profile 401 属正常情况。

- 上传、参数选择、提交和导出通过原网页控件操作；程序仅旁观网页自身的响应，确认 `(project_id, operator_id)`、进度及最终模型版本，不构造开发者 API 或私有生成请求。不会凭“最新缩略图”或仅凭预览画面判断完成。
- 参数按设置写入网页，网页实际接受的值会记录到任务中。网页对参数取整、模型版本更新、请求字段结构变化不会再触发一致性拦截；提交后以网站受理响应里的任务编号继续跟踪和下载。
- 支持自包含 GLB，最大 100 MB。自动任务导出的 ZIP 中若包含唯一、大小合规的 GLB，会自动解包回填；不使用压缩包路径写文件。普通手动下载的 ZIP / FBX 保留供手动处理。原始下载一直保留，过大的下载会取消。
- 回填遇到任务忙、文件无效或项目模型已被更换时，保留下载文件，工具栏显示原因；使用 **导入已下载 GLB** 重试即可。
- 提交前先将记录写入 `data/studio/<项目ID>/automation.json`。重启后点击继续只恢复已提交任务的跟踪/导出，绝不重放生成按钮。若旧版任务没有记录 ID 或自动跟踪受阻，先在工作台资产中点选需要的模型，再点击 **接续当前网页模型**；程序保存你选中的项目，通过网页导出 GLB，不再依赖任务编号或内部详情接口，也不重新生成。该导出方式重启后仍可继续。也可手动下载后通过工具栏 **导入已下载 GLB** 完成该任务。
- 导出前会重新读取同一项目的当前版本，版本不匹配或存在新的操作时暂停。网页改版导致控件无法唯一识别时，也会显示具体步骤并暂停。
- 登录会话存于 `data/desktop/profile/`，与本地工具界面隔离；视图交接和下载存于 `data/studio/<项目ID>/`。同一角色工作台重复打开会聚焦现有窗口，重新打开文件夹会准备最新裁切版本。
- 网页模式在前后端均阻止新建 API 建模任务。已有 API 任务仍可恢复查询；需要新建 API 任务时须在设置中切换模式。

### Tripo API 登录（独立计费）

先在设置中选择 **开发者 API**。双击 `tripo-login.cmd`，自行选择 API 账号所属区域并在浏览器完成授权；不要按语言猜测区域。或在设置中填写 API Key。**CLI 浏览器登录也使用 API 积分，不使用 Studio 会员额度。**

本项目固定使用本地 `tripo-cli@0.7.3`，不要求全局安装。可运行：

```powershell
node node_modules/tripo-cli/dist/cli.js docs --topic commands/generate
node node_modules/tripo-cli/dist/cli.js doctor
```

工具内的 API 连接检查不提交建模任务。Tripo 匿名统计在工具启动的 CLI 子进程中关闭。

## 推荐操作顺序

创建角色并配置模型接口后，按顶部四个阶段操作：

1. **角色设定**：填写完整角色描述，上传参考图，与设计助手讨论。点击 **保存设定，下一步**。
2. **角色图片**：根据设定生成完整角色三视图总图，也可导入图片。确认外观后点击 **使用这张图，进入部件拆分**；此阶段无需裁切。
3. **部件拆分**：从总图识别部件清单，或手动添加身体、发型、服装、配件。确认清单后进入部件建模。
4. **部件建模**：选择部件，依次完成 **独立部件图 → 部件三视图 → 裁切确认 → 生成模型**。左侧可切换部件，各角色和部件记住自己的浏览步骤；生成结果与完成状态独立展示。

后续处理从部件模型页进入 **对齐与绑定**：检测模板，调整旋转、缩放和偏移并生成对齐预览。绿色线框是模板人体，检查朝向、比例和关节位置。所有部件对齐后，返回角色总览，在 **后续处理 · 对齐、组装与导出** 中统一组装并绑定，导出 `.blend` / FBX / GLB，也可在 Blender 中打开。

生图使用仍与当前模板匹配的姿态信息；模板缺失或检测结果过期时自动使用默认 A-pose。裁切确认输出正面、一个侧面和背面三张 1024×1024 PNG，左右指角色自身，不做镜像伪造。Tripo 网页模式自动上传、生成并下载 GLB；API 模式通过 CLI 提交并保存任务 ID。原骨架的名称、层级和静止姿态不改变。

可以在部件模型页导入本地 GLB；历史整角色建模和导入入口位于部件建模总览的 **已有整角色模型 / 整角色建模** 中。浏览器只预览自包含 GLB；本地上传会拒绝外部纹理 / 文件引用，Tripo 返回的 FBX 可继续在 Blender 中处理。

## 输出与恢复

默认数据保存在 `data/`（已在 `.gitignore` 中排除）：

```text
data/settings.json                 # DPAPI 加密配置
data/tasks.sqlite3                 # 项目、消息、任务与文件索引
data/desktop/profile/              # 桌面配置与 Tripo 持久登录会话
data/studio/<项目ID>/               # 网页上传视图快照、原始下载和归属记录
data/studio/<项目ID>/automation.json # 当前网页自动化任务的恢复检查点
data/studio/<项目ID>/runs/          # 已结束的历史自动任务（开始新任务时归档）
data/projects/<项目ID>/             # 上传原图、拆图版本
data/outputs/<项目ID>/<任务ID>/      # 图片、模型、Blender 工程与报告
```

输出目录可在设置中更改，数据目录可由环境变量 `CHARACTER_FORGE_DATA` 更改。桌面版默认端口 8765，可用 `CHARACTER_FORGE_PORT` 指定本机端口。不要删除有用项目的索引数据库。

- 服务重启后，将运行中任务标为“中断”，不会自动重提付费请求。
- Tripo 有任务 ID 时，使用任务记录中的 **恢复查询**，仅继续等待 / 下载。
- 没有拿到任务 ID，或者生图超时 / HTTP 5xx 时，结果可能已经被受理；先核对供应商账单与任务记录。工具不把此类失败当成可以安全重试。
- 三视图、生图提示词、历史任务产物均按版本保留。当前界面展示最新结果，旧任务产物可从任务记录下载。

## 蒙皮质量边界

这是**可运行的第一版辅助工具**，不是生产级全自动拓扑 / 服装绑定系统：

- 目前对齐是整体旋转、等比缩放、平移，不做自动关节定位或局部人体变形。体型 / 姿态差异大时，应先在 Blender 中修正模型再导入。
- 最近表面插值会受衣物厚度、四肢距离、手指相邻表面影响。披风、长裙、头发可能需要额外骨骼、物理或人工权重修正。
- “无未绑定顶点”仅是基础检查，不等于动作无穿插或无变形问题。偏离权重源较远的顶点会提示。
- 不会把模板形态键 / 表情自动迁移到新网格，也不会自动生成控制器、IK 或 VRM。
- 新工程保留模板网格、形态键、骨架和动作数据；原网格隐藏。为便于检查，原激活动作被解除、NLA 轨道静音，动作数据保留，可在 Blender 中重新选择 / 启用。
- GLB / FBX 导出当前为绑定后的静止模型，**不包含动画剪辑**；动作库保存在 `.blend` 中。
- 源模板以 `--disable-autoexec` 打开，不执行工程自带脚本，不保存到源路径。

# 部件化角色工作流

角色总图生成或导入后，进入 **部件拆分**：

1. 点击 **从总图识别部件清单**（需要已配置支持视觉的 LLM），确认建议后逐项添加；也可手动添加基础身体、发型、上衣、外套、裤裙、鞋、手套和大型配件。鞋子、手套按一双建项，每张部件图和三视图均包含左右两只。点击部件图片或三视图可打开大图预览，支持放大、缩小、适应窗口和 Esc 关闭。
2. 进入 **部件建模**，点击对应部件的 **继续制作**，先生成独立部件图，再生成部件三视图。部件图以创建时的角色总图为参考，三视图以该部件图为参考；每次生图独立计费，失败不会自动重试。
   对提取结果不满意时，在 **部件修改要求** 中描述要调整的颜色、结构或细节，点击 **按要求修改当前部件图**。程序使用当前部件图作为编辑参考，成功后更新部件图并清除旧三视图、裁切、模型与绑定关联，随后可重新生成匹配的三视图。失败保留当前结果，历史图片仍可在任务记录中下载。
3. 确认三视图裁切后，进入 **生成模型** 使用 Tripo 一键建模。需要二次拆分的部件，在 **部件建模选项** 中勾选 **Tripo 二次智能拆分**：程序使用三角面生成，完成后进入智能拆分并选择 **第二档 6–15 个部件**，等待完成后导出 GLB。二次拆分按网站额度计费，生成和拆分分别保存提交记录，重启/继续不会再次提交。
   **当前部件面数** 可单独填写，点击 **保存面数设置** 后用于该部件后续建模。留空并保存则跟随当前模式的全局默认面数；网页会员和 API 建模都支持。已开始的网页任务继续使用启动时保存的面数。
4. 每个部件进入骨架页，生成对齐预览并调整旋转、比例、位移。初始位置按身体部位估算，仍需确认与绿色模板匹配。服装可转移表面权重；硬质配件、短发可选择单骨骼绑定并填写模板骨骼名。长发独立摆动需要在 Blender 中追加发骨与权重。
5. 返回角色总项目，点击 **组装全部部件并绑定**，生成共享模板骨架、保留独立网格与材质的 Blender / GLB / FBX。部件变化后需重新组装。

资产自动归集到配置的输出目录下 `<角色ID>/`，部件位于 `部件/<名称_ID>/`。**整理并打开资产文件夹** 会将已有参考图、部件图、三视图、模型和绑定工程复制归集，并更新 `资产清单.json`；原始文件继续保留。
